# NailGlow Score Model V2 面试讲解稿

## 一句话定位

我在 NailGlow 中实现了一套两阶段、可解释的手型与美甲适配框架：第一阶段把视觉几何特征映射为大众感知的手型画像，第二阶段学习手型、肤色和款式之间的五维适配关系，并对低置信度图片拒绝评分。

## 30 秒版本

普通图生图只能展示试穿效果，不能可靠回答哪款更适合用户。我把生成和推荐拆开：使用 MediaPipe 提取 21 个关键点并完成四方向检测，形成标准化手型特征；再通过手型感知模型输出修长、纤细、掌宽和柔和度，结合款式向量和交互特征，由多输出 RandomForest 预测手型、肤色、风格、场景和美观度五个评分。训练按 handId 做 GroupKFold，避免同一只手的不同款式泄漏到训练集和验证集；预测还会结合图像质量、训练分布和森林分歧输出置信度，低置信度时不再返回固定假分数。

## 90 秒版本

NailGlow 中我负责实现的一个核心模块，是可解释的多模态试穿和个性化适配评分。

我没有让图生图模型同时负责展示和打分，因为生成模型的主观评分不稳定，也很难用真实问卷持续训练。因此系统被拆成两条链路：图生图服务负责生成试穿图，评分模型只负责判断用户手型和具体款式是否适配。

评分框架是两阶段的。第一阶段使用 MediaPipe Hand Landmarker 提取 21 个手部关键点，并针对手机照片方向不固定的问题依次尝试 0、90、180、270 度。关键点识别后，系统提取掌长掌宽比、五指独立长度、指长均衡度、张开程度、拇指角度、手部深度、指尖肤色、曝光、清晰度和构图质量等特征。模型把这些可测量特征映射为修长程度、纤细程度、手掌宽度和轮廓柔和度四个大众感知轴。

第二阶段把手型画像、款式长度、圆润度、色温、复杂度和光泽度组合起来，同时构造长度匹配、圆润度匹配、色温匹配等交互特征，再使用多输出 RandomForest 同时预测五个维度。总分权重不是写死的，而是通过问卷的整体推荐分学习非负权重。

为避免数据泄漏，训练不是随机拆行，而是按 handId 做五折 GroupKFold，同一只手的所有款式只能出现在同一折。系统记录每个维度的 MAE、RMSE、R2、Spearman，以及整体推荐的 NDCG@3。运行时还根据输入质量、是否处于训练分布、森林内部预测分歧和样本支持度计算置信度；检测不到手或置信度不足时，仍展示试穿图，但明确返回不评分。

## 完整模块边界

```text
图像输入层
  -> 文件校验、方向恢复、质量检测

手部感知层
  -> 21 点关键点
  -> 38 个手部/图像输入特征
  -> 4 维大众感知手型画像

款式匹配层
  -> 手型特征 + 5 个款式属性 + 13 个交互特征
  -> 56 维兼容性输入
  -> 5 维适配评分

决策解释层
  -> 学习得到的总分权重
  -> 置信度、拒绝评分和推荐原因

反馈训练层
  -> 4 维手型感知问卷
  -> 5 维款式适配问卷
  -> candidate / active / backup 模型版本
  -> GroupKFold 指标与激活门禁
```

## 演示数据如何表述

当前演示训练数据是确定性模拟数据：180 个手型、5 个款式、48 个模拟评分者，每个手型款式组合 7 份评分，共 6300 份原始响应，聚合为 900 个训练样本。

模拟数据五折结果为：整体 MAE 约 1.48、Spearman 约 0.76、NDCG@3 约 0.996。这些数字只能证明训练、验证、排序和模型产物链路能够运行，不能描述成真实用户效果或线上提升。

项目现有手图的单次烟雾测试成功识别 21 个关键点，输出 5 个适配维度、4 个手型画像维度及约 0.82 的置信度。单样本结果也不能当成模型整体准确率。

## 高频追问

### 为什么不是端到端深度学习？

当前数据规模和业务阶段更适合结构化模型。关键点与款式属性具有清晰业务含义，RandomForest 对小样本和非线性交互比较稳健，CPU 部署成本低，并且能通过特征重要性和交互项解释结果。后续真实样本足够后，可以把手部分割或视觉编码器作为新的特征来源，而不必推翻问卷和验证框架。

### 为什么拆成两个模型？

“手看起来修长还是丰润”与“这个款式是否适合这只手”是两个不同任务。拆分后，手型画像可以跨款式复用，款式匹配也能够显式利用两者交互，训练标签和产品解释都更清晰。

### 如何防止数据泄漏？

同一只手会对应多个款式，如果按行随机切分，模型可能在验证集中再次看到同一只手。V2 使用 handId/groupId 做 GroupKFold，把一只手的所有款式锁在同一折。

### 置信度怎么计算？

它不是直接使用模型最大概率，而是组合四类证据：MediaPipe 检测和图片质量、输入是否落在训练集 p01/p99 分布内、随机森林各棵树是否一致、训练样本支持度。低置信度时返回 scored=false。

### 问卷为什么用 0 到 100？

0 到 100 便于输出连续评分，但界面提供 0、50、100 的语义锚点，减少不同评分者对数字的理解偏差。手型感知和款式适配分开填写，避免“觉得款式好看”反向影响手型标签。

### 现在还有什么局限？

当前演示模型主要依赖手部关键点，MediaPipe 不能直接测量真实指甲床边界或手指轮廓厚度；模拟问卷也不能替代真实人群研究。下一阶段应加入真实手型独立问卷、手部/指甲分割、评分者一致性分析和不同人群分层评估。

## 不要说错的三句话

- 不要说“模型评估生成图片质量”；它评估的是原手图和款式的适配关系。
- 不要说“模拟数据证明线上准确率”；它只验证 Demo 训练链路。
- 不要说“实现了新的深度学习算法”；更准确的是两阶段可解释推荐框架和工程闭环。
